= Orrery architecture
:toc: macro

The architecture of Orrery, in the https://arc42.org[arc42] template, with the
https://github.com/avrilfanomar/extensions-for-arc42[links and triggers extensions]
so that every decision names what it serves, who owns it and when it is due
for another look. The decisions themselves live one per file in
link:adr/[`docs/adr`] and are included in §9.

Sections 3 to 8, 10 and 12 are left out. The README covers the context, the
layout and the runtime story. The dogfood model
(`apps/server/src/dogfood/model.ts`) states every quality requirement as a
measured node, so it is the record of §10.

[[section-architecture-constraints]]
== 2. Architecture constraints

The invariants. `CLAUDE.md` restates them for contributors, and the suites
named there enforce them.

* [[con-log-is-state]]**The event log is the only state.** A stored event is never changed. A correction is a new event, and every projection can be thrown away.
* [[con-decide-gate]]**`decide` is the only gate.** Every rule that protects the model lives in one pure function, and the API, the seed and every importer go through it.
* [[con-unknown-not-green]]**Unknown never rolls up as green.** No rule and no rollup strategy may turn missing evidence into a pass.
* [[con-definition-in-force]]**A reading is judged against the definition in force when it was observed.** History is never re-judged by today's definition.
* [[con-core-pure]]**The domain core is pure.** It uses no Node or browser API, so the server and the console run the same code.
* [[con-core-no-integration]]**Core names no integration.** A query language, a source kind or a code host is a module, installed in one place.
* [[con-one-process]]**One process, one local log.** The PoC is a single server writing a single JSONL file. There is no cluster, database or tenancy.

[[section-technical-risks]]
== 11. Risks and technical debt

Known and accepted for a PoC. Each one leads to the decision that took it on.

=== Risks

* [[risk-identity]]**No identity.** Anyone who can reach the API can change the model. Authors name themselves, and a request without one is signed "you", so the audit trail is only as good as the header and nothing is non-repudiable. The ingest token guards readings only.
* [[risk-open-reads]]**Reads are open, and the server speaks plain HTTP.** Anyone who can reach it reads the whole universe, binding queries included. Nothing limits the request rate. With remote access allowed, the query oracle is back for that network, by design.
* [[risk-no-erasure]]**The log cannot forget.** An append-only log can never erase a name or a typed value. Removable personal data would need encryption per subject, or a log that keeps references instead of values.
* [[risk-server-clock]]**Staleness trusts the server's clock.** A clock that runs behind makes stale readings look fresh. A clock that runs ahead errs safe.
* [[risk-unit-mismatch]]**A query in the wrong unit reads in that unit.** A ratio bound to a percentage target reads a hundred times too good, and nothing can check that in general.
* [[risk-moved-yardstick]]**Moving the yardstick can turn a status green.** Relaxing a target or deprecating a node in breach needs a reason and shows in the change feed. Nothing marks that the change, not the system, made it green.
* [[risk-lock]]**One writer per log rests on a pid lock.** Taking over a stale lock can race, a reused pid can make a dead writer look alive, and the lock means nothing across machines or on a network file system.

=== Technical debt

* [[td-projection]]**Every request re-projects the whole log.** That holds for thousands of events, not millions of readings. Each open console also costs a full projection every 5 s, changed or not.
* [[td-batch-atomicity]]**A webhook batch is not atomic across a crash.** A kill partway through can leave part of a batch that was never acknowledged. Closing it needs a commit marker, which is a new event format.
* [[td-console-tests]]**The console has no unit tests.** Its share of each README claim (drill-down, one level below the focus) and the not-live warning are held only by the browser smoke test.
* [[td-a11y]]**Accessibility is checked by machine only.** Nobody has used the console with a screen reader, by keyboard alone or with magnification. The outline has no arrow keys, and the chart has no text form.
* [[td-observability]]**No access logs, metrics endpoint or readiness check.** The server logs warnings and errors only, and exposes nothing for Prometheus to scrape.
